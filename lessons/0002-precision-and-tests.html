02 · Define the boundary

TL;DR — A useful rule catches the intended syntax and leaves unrelated code alone. Tests express that boundary better than an informal promise.

Same intent, different syntax

it.only() uses an identifier property. it["only"]() uses a computed literal property. Read member.computed before interpreting member.property.

const name = member.computed
  ? member.property.type === 'Literal' ? member.property.value : null
  : member.property.name;

Test both sides

Open tests/no-focused-tests.test.js. Valid cases must produce no reports. Invalid cases must produce the expected message. The computed-property case also checks the diagnostic span. Our pinned Oxlint RuleTester uses zero-based columns.

Practice a counterexample

Add test['only']() as an invalid case and test['skip']() as a valid case. Run npm test. Then temporarily break the computed-property branch and confirm the new test fails; restore it afterwards.

Limits to explain in your own words

The rule matches names, not imported bindings. A local object named it can be reported. Aliases, chained it.only.each(), template-literal properties, and dynamic property names are outside this contract. Supporting imported bindings would require scope analysis and new cases.
